# Agent safety on the user's machine (hard rules)

Every rule below comes from a real incident while building a game with this
pipeline. They bind the orchestrator and every subagent it dispatches; put
them into every coder/verifier/fixer brief that may run tools.

| Rule | Why (what happened) | How |
|---|---|---|
| **Never inject global keyboard or mouse input** (`SendInput`, `keybd_event`, `SetForegroundWindow` + keys, AutoHotkey). | A synthetic SPACE meant for the simulator's unfold view landed in the user's call app and unmuted their microphone. | Drive the simulator only through its MCP server, its CLI/env switches, or messages posted to its own window handle. If a feature needs a real key press, the USER presses it. |
| **No window may appear over the user's screen** from an agent's own checks. | Off-screen/"no-activate" launches still popped simulator windows over the user's work. | Self-checks run the simulator headless (stock headless mode or the hidden-launch wrapper that kills the process by PID the moment any of its windows becomes visible). A visible simulator is never started or offered: it is an internal checking tool, and the user plays on their cube. |
| **Never play audio from test runs.** | Test simulators played placeholder sounds into the user's headphones. | Headless runs have audio stubbed; game test/debug builds compile sound out (a `<GAME>_MUTE` / debug define). Judge sounds by analysis (`sound_kit.py inspect`: duration, loudness, spectrum, envelope), never by playing them. Only the visible build the user asked for may make sound. |
| **Never kill processes by broad names or patterns.** | A cleanup step killed the user's own Codex sessions. | Keep the PID of everything you start and stop exactly those PIDs. |
| **No commits, pushes, PRs or messages without an explicit request.** | The user owns their repository and their accounts: nothing is published or sent in their name unasked. | Leave changes in the working tree, summarise, ask. |
| **No credentials.** Never type passwords or API keys; never ask for a paid-API key when a subscription path exists. | Image generation runs on the user's ChatGPT plan through the Codex CLI. | If a login is missing, the user runs `codex login` / signs in themselves. |
| **No paid API without the user's explicit opt-in.** Autonomous mode, the `YOLO` token and its confirmation are not consent; a key that is merely configured is not consent. | Image generation runs on the user's ChatGPT plan; a key set for something else once paid for images. | Only the tool the user chose: a Codex login or a key found on the machine is never used on its own (`image_providers.resolve_provider()` returns nothing without a choice). Codex when chosen (it must report a ChatGPT login: a Codex CLI logged in with an API key bills that key, so `art_codex.py` refuses it). Nothing chosen, or no Codex → the procedural style (agent-drawn in code, final quality), `STAGE3_ASSETS.md` §2. `WOWCUBE_ALLOW_PAID_IMAGES=1` / `--allow-paid` only when the user asked for a paid provider and agreed to pay per image. A local Stable Diffusion on `localhost` / `127.0.0.1` is free and needs no opt-in. |
| **Downloads only after the user approves the list** (file, source, licence, size). | Sound packs and libraries come from the internet. | Propose CC0 sources with licence + size; download into a fresh folder; never execute downloaded files. |
| **Tests and smoke runs never reach a paid API.** | A smoke test that switched Codex off fell through to an `OPENROUTER_API_KEY` set in the user's environment and paid for an image. | The scripts ignore paid keys unless `WOWCUBE_ALLOW_PAID_IMAGES=1` / `--allow-paid` is set (set it only when the user asked for a paid provider); still remove `OPENROUTER_API_KEY`, `IMAGE_API` and similar keys from the environment of every test/smoke run (or mock the provider). |
| **The store upload sends the game to WowCube's servers: ask once first.** Only the verified `.oct` from `dist/`; the install link (with its `?password=`) goes only to the user. | Delivery is a store upload with an install QR code the user scans with their phone; nothing goes to a cube from this computer. | `scripts/store_upload.py --yes` only after the user's yes ("Make an install link and a QR code so you can put the game on your cube from your phone? (The game file is sent to WowCube's servers for that.)"); never another file, never a Bluetooth upload in the user's flow. |
| **A resource found on the machine is not the user's until they say so.** | A family PC had a logged-in Codex and a paid key that belonged to someone else. | Never pre-select or default to a detected Codex login, API key or paired device; never print key or credential names unless asked; at most ask "I see ChatGPT/Codex logged in on this computer: is it yours, and may I use it?" |
| **No windows, no prompts the user did not expect from installs.** After installing tools, Claude Code must be restarted to see them. | An install inside the running session left every later shell with the old PATH. | Tell the user to close Claude Code and open it again in the same folder; continue only after they confirm, then re-check. |
| **The environment bootstrap is one approval, asked once, and installs are quiet.** | Toolchain installers and installing the simulator put software on the machine; a `--passive` installer still shows its window. | One message lists it all (orchestrator entry check 3): the toolchain installs (`check_env.ps1 -Install`: silent winget installs, the Visual Studio installer with `--quiet`, no installer windows; Linux/macOS: the package manager line `check_env.sh` prints, never `curl … \| sh`) and getting the bundled simulator (`tools/sim/get_sim.*` installs the prebuilt simulator the plugin carries (about 6 MB on Windows)). `check_env` reports a missing simulator as `[MISSING]` (exit 2) even when the plugin carries it, and `new_app` gets it only with `-GetSim` / `--get-sim`, which the orchestrator passes after this approval. Run them only after the user agreed, only through those tools; afterwards checks and builds use what is installed. |
